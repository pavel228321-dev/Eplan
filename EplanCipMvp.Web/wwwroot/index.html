EplanCipMvp

Нумерация кабелей и жил в проекте EPLAN по правилам (сейчас — кабели). Прежняя генерация листов из доноров — в свёрнутых блоках ниже.

Как это работает

Кратко — что происходит между браузером, этой программой и EPLAN.

Архитектура

Браузер — это просто «пульт». Вся работа с EPLAN идёт в программе EplanCipMvp.Web.exe, которая запущена на этом же компьютере и поднимает локальный сервер (localhost:5177). Страница в браузере отправляет туда обычные запросы, а сервер сам подключается к установленной у вас EPLAN через её собственный API (COM) и открывает нужные проекты.

Из этого следует: работает только пока запущен EplanCipMvp.Web.exe на этом же компьютере, где стоит EPLAN; открыть страницу с другого компьютера бессмысленно — без локального сервера на машине с EPLAN ничего не подключится.

Нумерация кабелей (основное)

Укажите папку Bin вашей EPLAN и проект (.elk), нажмите «Подключиться» — доноры и xlsx не нужны. В карточке «Нумерация кабелей»: «Считать кабели» показывает все кабели проекта и имя, которое даст первое подходящее правило; «Записать отмеченные» переименовывает только отмеченные строки (вместе с жилами), затем перечитывает проект и сверяет результат. Первый прогон — на копии проекта. При любой ошибке пришлите файл EplanCipMvp.Web.log рядом с программой.

Генерация страниц из доноров (прежние функции)

Всё, что ниже, относится к ним: поля донорских проектов и xlsx — в свёрнутом блоке на карточке подключения.

Шаг 1 — Подключение

По кнопке «Подключиться» сервер запускает API EPLAN и открывает указанные вами проекты: донорские (1260, и при необходимости 1166 — источники готовых листов схем) и целевой (1364 — куда копируем).

Опционально — «Создать как полную копию донора 1» (Шаг 0): если включить этот чекбокс и указать путь для ещё НЕ существующего файла, сервер сначала скопирует донор 1 целиком (весь проект, не отдельные листы) и откроет эту копию как целевой проект — вместо пустого проекта из шаблона. Если файл по указанному пути уже есть, копирование пропускается, он просто открывается как есть. Схемы CIP-моек у разных объектов обычно похожи, поэтому это может сразу дать бо́льшую часть содержимого «бесплатно» — а дальше Шаг 3 (ниже) приводит количество страниц и теги в соответствие с конкретным объектом.

Шаг 2 — Типы устройств и донор-страницы

Для каждого отмеченного типа устройства (насос с ПЧ, клапан, датчик, модуль ПЛК и т.д.) инструмент ищет в доноре подходящие страницы-кандидаты и даёт выбрать нужную. Если точного совпадения нет, страница может быть предложена «по аналогии» (с пометкой ⚠) — такие стоит перепроверить вручную после копирования.

Копирование

По кнопке «Скопировать» инструмент берёт выбранную донор-страницу и переносит её в целевой проект, автоматически подстраивая: обозначения устройств (перетэговка под нумерацию 1364), артикулы (если в целевом проекте другая модель/поставщик), адреса ПЛК и подобное — то есть не рисует схему с нуля, а адаптирует уже готовую.

Шаг 3 — Реконсиляция (после полного копирования)

Если использовался Шаг 0, страницы группы устройств (насосы ПЧ, клапаны/датчики) уже физически есть в целевом проекте — но под донорскими тегами, и их количество может не совпадать с реальным объектом. «Показать план» считает, без изменений в проекте: сколько страниц есть, сколько нужно по спецификации, что будет продублировано (если нужно больше) и что будет удалено (если нужно меньше). «Применить» реально выполняет это — дублирует/удаляет/переименовывает — и активна только после того, как вы увидели план для тех же отмеченных групп.

Важно: удаление страниц (Page.Remove()) необратимо — это единственное разрушительное действие во всей программе. Сначала внимательно смотрите список «будет удалено» в плане, и по возможности пробуйте на резервной копии проекта, особенно первые несколько раз. Модули ПЛК (DP) в реконсиляцию пока не входят — там один и тот же фильтр страниц покрывает и титульные листы, и детализацию, и программно надёжно различить их среди уже существующих страниц нечем.

Таблица параметров ПЧ

Отдельное необязательное поле на Шаге 1 — можно указать xlsx с параметрами насосов (модель ПЧ, наличие пускателя, состав DI/DO/AI/AO, Profibus и т.п.). Сейчас это только чтение и предпросмотр (таблица показывается ниже после подключения, чтобы проверить, что колонки распознаются верно) — на выбор донор-страницы или на реконсиляцию эти данные пока не влияют. Это задел: следующий шаг — использовать её как источник правды для автоматического подбора донор-страницы вместо ручного выбора.

Важно: и обычное копирование, и реконсиляция подбирают/дублируют готовую страницу из уже существующих вариантов — программа не рисует схему «с нуля». Если для нужной комбинации подходящей страницы нет ни в донорах, ни в уже скопированном целевом проекте, такую страницу нужно дорисовать вручную.

3 Реконсиляция после полного копирования

Приводит количество УЖЕ СУЩЕСТВУЮЩИХ страниц группы в целевом проекте в соответствие со спецификацией: где по спецификации устройств больше — дублирует существующую страницу внутри проекта; где меньше — удаляет лишние страницы (необратимо, Page.Remove); везде — переименовывает теги.
