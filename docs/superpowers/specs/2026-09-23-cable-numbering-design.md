# Нумерация кабелей по настраиваемым правилам (EplanCipMvp) — дизайн

Дата: 23.09.2026. Статус: согласован с пользователем (Павел, Aprotec).
Этап 1 из 2: **кабели**. Этап 2 (жилы/провода) — отдельная спецификация позже.

## Цель

Одной кнопкой назначать имена (DT) всем кабелям проекта EPLAN P8 2.9 (1364)
по правилам «как в 1260», причём правила задаются и меняются в самой
программе, без переписывания кода. Поток: **Считать → Предпросмотр → Записать
(только отмеченное)**.

## Правило 1260 (источник истины — перечень кабелей 1260, 237 строк)

| Случай | Имя | Пример из 1260 |
|---|---|---|
| Цель в `+FIELD`, кабель из шкафа периферии (ET101/ET102) | `W` + DT полевого устройства | `C04VP01` → `WC04VP01` |
| Цель в `+FIELD`, кабель из главного шкафа E01 | `W` + DT устройства **начиная с первой цифры** | `C01M01` → `W01M01`, `T32GS01` → `W32GS01` |
| Несколько кабелей к одному устройству | суффикс `.1`, `.2` … (только если кабелей > 1) | `WC04FT01.1`, `WC04FT01.2` |
| Выравнивание потенциалов (1 жила, H07V-K) | `WEQ` + номер шкафа-источника | `WEQ101` |
| Питание шкаф→шкаф (3 жилы, цель в E01 на `1X2`) | `W21` + 2 последние цифры шкафа-источника | `W2101` |
| Profinet (`ETHERLINE PN`) | `WPN-` + короткое место источника | `WPN-ET101` |
| Без источника/цели (`WPN-PC1`, `WEX-*`) | правила нет → имя вручную | — |

## Модель правил (EplanCipMvp.Core, без EPLAN, тестируемо)

`CableRule { Name, Enabled, Condition, Template }`. Правила проверяются сверху
вниз, **срабатывает первое подходящее**. Кабель без подходящего правила
получает статус «нет правила» и не меняется, пока пользователь не впишет имя
вручную.

**Condition** — все заполненные поля должны совпасть (пустое = «любое»):
- `SourceLocation`, `TargetLocation` — маска места установки (`*`-шаблон,
  регистр не важен), например `+FIELD`, `+CP.ET*`;
- `TypeContains` — подстрока типа кабеля (`ETHERLINE PN`, `H07V-K`);
- `CoresTotal` — число жил (точное);
- `TargetDevice` — маска DT хотя бы одного устройства на стороне цели
  (`*VP*`, `1X2`).

У каждого конца кабеля может быть несколько устройств (клеммник + модуль ПЛК +
экран). Для подстановок берётся первое устройство конца, чьё место
установки подходит под `SourceLocation`/`TargetLocation` правила (если маска
пустая — первое устройство конца).

**Template** — текст с подстановками:
- `{Устройство}` — DT полевого устройства на стороне цели, без `-` и без
  места установки (`C04VP01`); `{Устройство:от_цифры}` — начиная с первой
  цифры (`01M01`);
- `{МестоИсточника}` / `{МестоЦели}` — последний сегмент места установки
  (`+CP.ET101` → `ET101`);
- `{ШкафИсточника}` — цифры из `{МестоИсточника}` (`101`);
  `{ШкафИсточника:N}` — последние N цифр (`{ШкафИсточника:2}` → `01`);
- `{.N}` — суффикс `.1/.2/…` среди кабелей с одинаковым базовым именем;
  пусто, если кабель с таким базовым именем один. Порядок суффиксов —
  порядок чтения из EPLAN (лист, затем позиция); при необходимости
  правится вручную в предпросмотре.

**Пустые подстановки**: если хоть одна подстановка шаблона (кроме `{.N}`)
получилась пустой (например, у кабеля нет источника), правило считается
не сработавшим и проверяется следующее.

**Ориентация кабеля**: в EPLAN полевое устройство может оказаться и на стороне
«источника». Движок проверяет каждое правило сначала для кабеля как есть,
затем с переставленными источником и целью; срабатывает первое совпадение
(в любой ориентации) по порядку правил.

Правила хранятся в JSON-файле рядом с программой (`cable-numbering-rules.json`).
Встроенный пресет **«Как 1260»** (кнопка «Сбросить к пресету») в порядке:
1. Profinet: `TypeContains=ETHERLINE PN` → `WPN-{МестоИсточника}`
2. PE: `TypeContains=H07V-K`, `CoresTotal=1` → `WEQ{ШкафИсточника}`
3. Шкаф→шкаф: `TargetLocation=+CP.E01`, `TargetDevice=1X2` → `W21{ШкафИсточника:2}`
4. Главный шкаф→поле: `SourceLocation=+CP.E01`, `TargetLocation=+FIELD` → `W{Устройство:от_цифры}{.N}`
5. Периферия→поле: `TargetLocation=+FIELD` → `W{Устройство}{.N}`

## Поток в программе (EplanCipMvp.Web, новая карточка «Нумерация кабелей»)

1. **Считать** — читает все кабели целевого проекта: текущий DT, место
   установки, источник и цель (место + DT устройства + клеммник), тип, число
   жил. Проект не меняется.
2. **Предпросмотр** — движок правил (Core) считает новое имя по каждой
   строке. Таблица: текущее имя · источник · цель · тип · сработавшее правило ·
   новое имя (редактируемое) · ☐ применить. Галочки по умолчанию: отмечены
   строки с пустым DT или DT, содержащим `?`; строки, где DT уже есть и
   отличается от нового, **не** отмечены — пользователь решает сам.
3. **Записать** — пишет только отмеченные строки, затем перечитывает кабели
   и показывает, что реально записалось.

Редактор правил в той же карточке: таблица правил (добавить, изменить,
вверх/вниз, вкл/выкл, удалить), «Сохранить», «Сбросить к пресету 1260».

## Защита от ошибок

- **Дубли**: если два кабеля получают одно новое имя, или новое имя совпадает
  с DT кабеля, который не переименовывается, строки подсвечиваются и запись
  по ним блокируется до исправления.
- Пишется только отмеченное; по каждой строке отдельный try/catch и лог —
  ошибка одного кабеля не прерывает остальные.
- Первый живой прогон — на копии проекта (напоминание в интерфейсе).

## Запись в EPLAN

Переименование — `NameService.RenameDevice(cable, newNameParts,
bRenameCDPsAlso: true, bKeepDescribingProps: true)`: по документации API 2.9
переименовывает устройство вместе с жилами кабеля (CDP), иначе жилы
отвязались бы от кабеля (связь кабель↔жилы идёт по имени). Новое имя
раскладывается в `NameParts` текущего кабеля (место установки сохраняется):
`FUNC_PREFIX` = "", `FUNC_CODE` = ведущие буквы, `FUNC_COUNTER` = остаток.
После записи — перечитать и сверить `VisibleName` и число жил под кабелем
(`CableConnections`) до/после; расхождение — явная ошибка в логе.

## Проверка

Прототип правил (Python, 23.09.2026) на перечне 1260: 228/228 кабелей с
правилом получили ровно имя из 1260, 0 расхождений, 9 — «нет правила».

- **Автотест движка на реальных данных 1260** (`EplanCipMvp.Core.SelfTest`):
  фикстура из перечня кабелей 1260 (источник, цель, тип, число жил →
  ожидаемый DT). Пресет «Как 1260» должен воспроизвести имена 1260; кабели
  без источника/цели (`WPN-PC1`, `WEX-*`) — статус «нет правила».
  Нормализация фикстуры: DT устройства цели = текст в `[...]` у `+FIELD` с
  отброшенными концевыми не-буквенно-цифровыми символами (`BM02VP05+` → `BM02VP05`).
- Тесты детекции дублей и логики галочек по умолчанию.
- Сборка без ошибок; живой прогон — у пользователя на копии 1364.
