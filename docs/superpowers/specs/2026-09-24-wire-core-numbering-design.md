## Обозначение жилы (31004)

Жила назначается штатным механизмом EPLAN «Назначить» (навигатор устройств):
`шаблонЖилы.Assign(провод)` — свободная жила-шаблон кабеля (`Cable.Connections`,
`IsTemplate && !IsCoveredTemplate`, её 31004 из артикула) переносится на провод,
пересечённый линией кабеля.

Выбор жилы для провода (по 1260), первое сработавшее:
1. Жила, чьё обозначение равно клемме полевого устройства на этом проводе
   (`-WGS101` к клеммам `1/3/4` → жилы `1/3/4`).
2. Клемма `PE` / символ заземления → жила `GNYE` (или `GN/YE`, `GNYE` без учёта регистра и `/`).
3. Иначе — следующая свободная жила в порядке шаблона кабеля (`U/V/W` мотора → `1/2/3`;
   цветной кабель → `WH`, `BN`… по порядку артикула).

Провода кабеля перебираются в порядке: лист, затем X, затем Y. Уже назначенные
жилы не трогаются (если пользователь не отметил строку). Кабель без артикула
(нет шаблонов жил) → статус «нет жил в артикуле», жила не назначается.
Жил меньше, чем проводов → лишние провода — «не хватает жил», не назначаются.

## Номер провода (31011): правила 1260

Номер присваивается **узлу** — проводам, связанным общим контактом (функция + вывод;
две стороны клеммы — разные контакты, поэтому `32L47` и `32M04-U` на `-1X31:1` — разные
узлы). Правила проверяются сверху вниз, срабатывает первое подходящее; опорный конец —
любой конец узла, подходящий под маски правила (поэтому ориентация провода не важна).

| № | Провод подключён к… | Шаблон пресета | Примеры 1260 |
|---|---|---|---|
| 0 | клемме `PE` | `PE` | `PE` |
| 1 | клемме устройства в `+FIELD` | E01: `{Устройство:от_цифры}-{Клемма:буквы}`; иначе `{Устройство}-{Клемма:буквы}` | `-T32M04`:U → `32M04-U`; `GS101-3`, `VLT01-1` |
| 2 | клемме модуля ПЛК (DT `*A*.*`) | `{МодульПЛК:цифры}{Клемма:2}` | `-1A1.1`:1 → `11101`; `-1A2.1`:1 → `12101`; `-1A4.1`:2 → `14102` |
| 3 | потенциалу с именем | `{Потенциал}` | `1L1`, `1L121`, `31L+`, `1M`, `N`, `PE` |
| 4 | силовой клемме (`?`, `?L?`, `?T?`) аппарата группы (DT `??QF*`, `??KM*`, `??U*`) | `{Группа}L{Номер:последняя}{Счётчик}`, порядок по строкам | `-32QF04` → `32L41`…`32L43`, дальше по цепи `32L44`…`32L49`; `-01QF01` → `01L11`… |
| 5 | всё остальное в шкафу `+CP.*` (цепи управления) | `{Счётчик}`, начало 121, порядок по столбцам | `121`, `122`… |

Нет подходящего правила → статус «нет правила», провод не меняется, пока
пользователь не впишет номер вручную.

### Подстановки

- `{Устройство}` — DT устройства на конце без `-` и без места установки (`T32M04`);
  `{Устройство:от_цифры}` — начиная с первой цифры (`32M04`). Общая с кабелями
  логика (`DeviceNameSplitter`/`DeviceTagParser`).
- `{Клемма}` — обозначение контакта (`Pin.Designation`: `1`, `U`, `DI0`→ берём
  обозначение клеммы, не имя канала); `{Клемма:2}` — дополнить нулями слева до 2
  знаков (`1` → `01`); нечисловая клемма в `{Клемма:2}` → подстановка пустая.
- `{МодульПЛК:цифры}` — все цифры DT модуля ПЛК по порядку (`1A2.1` → `121`).
- `{Потенциал}` — имя потенциала провода (`Pin.Potential`), пусто если не задано.
- `{Группа}` — ведущие цифры DT аппарата (`32QF04` → `32`, `01QF01` → `01`);
  `{Номер:последняя}` — последняя цифра концевого номера DT (`04` → `4`).
- `{Клемма:буквы}` — только ведущие буквы клеммы, если они есть (`U1` → `U`), иначе клемма целиком (`3` → `3`).
- `{Счётчик}` — 1, 2, 3… (или с `CounterStart`) отдельно для каждого «места опорного конца +
  текста шаблона вокруг счётчика»: `{Группа}L{Номер:последняя}{Счётчик}` даёт `32L41…` внутри
  группы `32L4`, `{Счётчик}` с началом 121 — сквозной счётчик по шкафу. Порядок — поле правила
  `Order`: `Y` — по строкам (лист → сверху вниз → слева направо), `X` — по столбцам. Номера,
  выданные другими правилами или стоящие в узлах без правила, пропускаются.
- Пустая подстановка (кроме счётчиков) → правило не сработало, проверяется следующее.

### Условие правила (пустое поле = «любое»)

- `Location`, `Device`, `Terminal` — маски опорного конца (место, DT устройства, клемма);
  несколько масок через `;` (`??QF*;??KM*`);
- `OtherLocation` — маска места любого другого конца узла;
- `Potential` — да/нет/любое (есть ли у узла имя потенциала);
- `InCable` — есть ли в узле жила кабеля: да/нет/любое;
- `Order`, `CounterStart` — порядок и начало счётчика.

## Архитектура (как у кабелей)

- **Core** (`EplanCipMvp.Core/WireNaming/`, без EPLAN, автотесты):
  `WireModels` (`WireEnd { Location, DeviceTag, Terminal, IsPlc }`,
  `WireInfo { Id, Page, X, Y, CurrentName, CurrentCore, CableId, Potential, Ends }`,
  `WireRule`, `WireNamingRow`), `WireNamingEngine` (правила + счётчики),
  `CoreAssigner` (выбор жилы), `WireRulePresets` (пресет 1260),
  `WireRuleStore` (`wire-numbering-rules.json` рядом с программой),
  `WireApplyPlanner` (дубли, галочки по умолчанию).
- **App** (`WireNumbering.cs`, `WireNumberingSession.cs`): чтение всех
  соединений проекта (`DMObjectsFinder` → `Connection`; `StartPin`/`EndPin` →
  `ParentFunction` DT + место + `Designation`; `Pin.Potential`; CDP кабеля),
  запись 31011 в CDP, назначение жил `Assign`, перечитывание и сверка.
- **Gui**: вкладка «Нумерация жил и проводов» (панель по образцу
  `CableNumberingPanel`). **Web**: такая же карточка и `/api/wires/*`.

## Запись в EPLAN

- Номер провода: если у провода есть точка определения соединения (CDP) —
  пишем 31011 в неё. Если нет — ставим CDP штатным
  `Connection.PlaceAsConnectionDefinitionPoint(page, середина провода)`.
  Галочка «Ставить новые точки определения» (по умолчанию выкл. в первом
  прогоне) — без неё провода без CDP получают статус «нет точки».
- Жила: `template.Assign(connection)` внутри того же `LockingStep`.
- Всё — только отмеченное, отдельный try/catch и строка лога на провод.
  После записи — перечитать и сверить 31011/31004.

## Защита от ошибок

- Дубли номеров проводов (кроме потенциалов — у них одно имя на много проводов
  законно; дублем считается одинаковый номер у проводов с разными потенциалами
  или без потенциала) — подсветка, запись заблокирована.
- Галочки по умолчанию: номер пустой, содержит `?`, или дубль; жила не
  назначена. Отличающийся существующий номер — без галочки.
- Первый живой прогон — на копии проекта (напоминание в интерфейсе).
